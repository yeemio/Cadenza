# 质量存疑模块 PRD 文档

---

## 1. 基本说明

### 1.1. 业务理解

质量存疑用于把在库中有质量疑问的产品轴号标记为存疑。现场在 PDA「质量存疑」扫产品轴号，核对料品信息后确认，系统生成一条质量存疑记录，并把该码的质量状态改为存疑。Web 按生产部门查询存疑记录，对存疑的记录点「恢复」，把记录和码的质量状态改回正常。

```text
PDA 扫产品轴号（须在库、在库位、未存疑）→ 质量存疑确认
        ↓
生成质量存疑记录（当前状态 = 存疑），码的质量状态 = 存疑
        ↓
Web「质量存疑」点「恢复」→ 记录和码的质量状态 = 正常
```

**两端分工：**

- **Web**：按产品轴号、生产部门查询质量存疑记录；对存疑的记录执行恢复。
- **PDA**：扫产品轴号查看库位、仓库、托盘和料品信息，确认标记为质量存疑。

### 1.2. 字典说明

#### 质量状态

Web 列表「当前状态」使用，页面上不着色。

| 类型值 / 状态值 | 说明 |
| --------------- | ---- |
| 正常 | 未存疑，或存疑后已恢复。 |
| 存疑 | PDA 标记为质量存疑。Web 操作栏显示「恢复」。 |

## 2. Web 端

### 2.1. 质量存疑页面

#### 列表页面

##### 页面元素

**列表上的搜索条件**

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| 产品轴号 | 文本 | 模糊 |
| 生产部门 | 树形下拉 | 部门树；仅搜索，不出现在列表 |

**列表上面的按钮：**无

**列表展示字段：**

| 列名 | 说明 |
| ---- | ---- |
| 勾选列 | |
| # | 序号 |
| 产品轴号 | |
| 料品名称 | 多个用逗号隔开 |
| 规格 | 多个用逗号隔开 |
| 生产部门 | |
| 发起人员 | |
| 发起时间 | |
| 当前状态 | 见字典「质量状态」 |
| 操作 | |

**列表操作栏的按钮：**恢复

##### 交互

- 按发起时间倒序。
- 进入页面时，生产部门默认为当前登录人所属的第一个部门。
- 点「清空」清除全部搜索条件（包括生产部门），按空条件重新查询。
- 行可勾选，但本页没有按勾选执行的操作。
- 操作栏按钮显隐：
  - 恢复：仅当前状态为存疑时显示
- 点「恢复」不弹确认框，直接执行；成功后刷新列表；失败时提示系统返回的原因。

##### 逻辑

- 数据范围：PDA 质量存疑确认后生成的记录。本页不允许新增、编辑、删除。
- 生产部门：查询所选部门及其下级部门的记录。
- 生产部门取产品轴号所属生产订单的生产部门；发起人员、发起时间为 PDA 确认人和确认时间。

#### 恢复

##### 页面元素

无

##### 交互

无

##### 逻辑

- 执行后：该记录的当前状态改为正常，同时该产品轴号的质量状态改为正常。

## 3. PDA 端

> 扫码通过 PDA 侧边扫码键触发。系统返回键（侧滑、物理返回）不生效，只能点导航栏左侧「BACK」返回。接口返回失败时，由全局请求处理提示系统返回的原因。

### 3.1. 质量存疑页面

**入口：**主页「物流管理」分类下的「质量存疑」。

#### 列表页面

##### 页面元素

**导航栏标题：**质量存疑；左侧「BACK」。

**未扫码时：**页面中间红字「(请使用侧边按钮扫产品轴号)」。

**扫码后页头：**白底，每行左标签右内容。

| 字段 | 说明 |
| ---- | ---- |
| 产品轴号 | 标签与值都是蓝色；值为本次扫到的码 |
| 客户轴号（段长) | 格式「客户轴号 (段长)」 |
| 所在库位 | |
| 所在仓库 | |
| 所在托盘 | |

**卡片展示字段：**按料品一张卡片。

| 字段 | 说明 |
| ---- | ---- |
| 料品名称 | |
| 规格 | 无值显示 `N/A` |
| 颜色 | |
| 数量（单位） | |

**卡片上的按钮：**无

**页面按钮：**底部贴边整宽蓝色「质量存疑」，始终显示。

##### 交互

- 页头、卡片无值显示 `-`。
- 点「BACK」回到主页。
- 本页不分页，没有下拉刷新和上拉加载。

##### 逻辑

- 数据范围：本次扫到的产品轴号对应的码，按料品汇总；数量为该料品各码数量之和。

#### 扫码

##### 页面元素

无（使用侧边扫码键）。

##### 交互

- 扫到载具码（第 2 位为 E、F、M、P）：查询该码；成功后用页头和卡片替换未扫码提示，再扫会覆盖上一次结果。
- 扫到其它码：提示「请扫描正确的调拨产品轴号」。

##### 逻辑

- 查询时校验，不通过时提示括号内文案：
  - 该轴不存在关联料品，或扫的是托码（「该轴不存在关联料品,或扫描的是托码」）
  - 码未入库（「该轴未入库」）
  - 码没有库位（「该轴未在仓库中」）
  - 码已标记存疑（「该轴已标记存疑」）
- 扫码只查询，不改数据。

#### 质量存疑确认

##### 页面元素

确认框，标题「质量存疑」，内容「确定执行此操作吗」，按钮：取消、确定。

##### 交互

- 点底部「质量存疑」弹出确认框；点取消关闭。
- 点确定：
  - 成功：关闭确认框，提示「操作成功」，约 1.5 秒后回到主页
  - 失败：提示系统返回的原因，确认框保持打开
- 还没扫码就确定，提示「请传入二维码」。

##### 逻辑

- 确认时按「扫码」的规则重新校验。
- 执行后：
  - 生成一条质量存疑记录：产品轴号为本次扫到的码；料品编号、料品名称、规格、颜色为各料品去重后用逗号拼接；当前状态为存疑；生产部门取该码所属生产订单的生产部门；发起人员、发起时间为本次确认人和时间
  - 该产品轴号的质量状态改为存疑
