# 采购批次模块 PRD 文档

---

## 1. 基本说明

### 1.1. 业务理解

采购批次是 PDA「采购入库」扫码页点「确认收货」后生成的一次入库单元：对应采购订单行下的一批收货明细（含物料二维码、仓位、厂家批号等）。收货在 PDA 采购入库扫码页完成（见本篇 §3）；Web 端不手工新增批次，只做查询、修改、退货、删除与同步重试；点「明细」进入采购明细（二维码维度，另文）。采购订单由 ERP 推送，PDA 采购入库列表见《采购订单》§3。

**两端分工：**

- **Web**：采购批次列表查询、导出；修改 / 管理员修改；退货；删除 / 管理删除；合格同步重试 / 退货同步重试；跳转采购明细。
- **PDA**：采购入库扫码页（本篇 §3）：扫码录入收货明细、扫码删除、确认收货，生成采购批次。

##### 交互

- 点击数据行可勾选或取消勾选。
- 排序：按入库时间倒序，无入库时间的排在最后；入库时间相同按主键升序。入库时间不在列表展示。
- 选中合计：按单位分组累加入库数量，保留 4 位小数；无单位按「未知单位」。
- 汇总「质检中：N」：当前筛选条件下质检状态为质检中的批次数。
- 从采购订单「批次详情」或点采购单号进入时，带入采购单号、行项目号作为默认筛选。
- 点击批号或「明细」：跳转采购明细页，并带入批次、批号、采购单号、行项目号；用户在明细页清空搜索或重新搜索后，去掉批次带入条件。
- 操作栏按钮显隐：
  - 修改：质检状态为待质检或全部不合格，且合格同步状态不为已同步时显示
  - 管理员修改：始终显示，不受质检、同步状态限制
  - 退货：质检状态为全部不合格且入库状态非已退货时显示
  - 删除：同「修改」业务条件
  - 管理删除：始终显示，不受质检、同步、退货状态限制
  - 明细：始终显示
  - 合格同步重试：合格同步状态为同步失败，且质检状态为免检或全部合格时显示
  - 退货同步重试：退货同步状态为同步失败，且入库状态为已退货时显示（列表不展示退货同步状态列）

##### 逻辑

- 数据范围：由 PDA 确认收货后自动生成的采购批次；本页不允许手工新增。

##### 交互

- 仓库选项按物料分类（原料 / 成品）过滤；中转仓选项排除线边仓。
- 选线边仓：库位置空并置灰；未跳过中转时须选中转仓与中转库位。
- 选非线边仓或跳过中转：中转仓 / 中转库位置空并置灰；非线边须选库位。
- 至少保留 1 条收货明细，不允许空明细保存。
- 点行内删除：确认「确定删除本条采购收货数据？」后从表中移除该行，点确定提交后才生效。
- 点「批量修改」：弹窗默认带出所选第一行的值；提交后写回所选各行。空厂家批号 / 牌号 / 备注 / 生产日期不覆盖原值；数量强制覆盖；仓库、库位、中转仓、中转库位按弹窗值覆盖。批量弹窗内仓库、库位、中转联动规则同上。

##### 逻辑

- 可执行条件：普通修改同列表「修改」显隐；管理员修改不校验质检 / 同步状态。
- 同一批次入库仓库必须一致。
- 同一厂家批号下生产日期必须一致。
- 数量须大于 0。
- 执行后更新批次到货时间、入库确认时间及明细仓位 / 中转仓位 / 数量等；并回写订单行已收数量与订单状态、库存相关数据。

##### 页面元素

#### 扫码

##### 页面元素

无（使用页面「扫码」）。

##### 交互

- 点「扫码」按扫到的码处理：
  - 收原料的订单行只接受原材料码（R 类，10 位）；收成品的订单行只接受 E/F 类成品码。格式或类型不符提示对应文案（如「请扫描 E/F/R 类型料品二维码（自制成品/外购成品/原材料）」「收原料只能扫描 R 类型（原材料）料品码」「收成品只能扫描 E/F 类型（自制成品/外购成品）料品码」）。
  - 料品码合法：先做空码校验；该码已有收货数量、或本单已点保存过，弹出「扫码确认」：「当前二维码已收货 “物料名称” 数量单位，确定要继续收货吗？」，数量 = 系统已记收货数量 + 本机已保存同码数量；点「确认」后打开扫码录入弹层（见下），不确认则不打开。
  - 该码正处于校验中、或已在队列中，再扫提示「该料品码已在本次扫描中，请勿重复扫描」。
  - 其它码：枪机半截码、刚成功扫码后的杂讯静默忽略，其余提示格式或类型错误。
- 扫码时若该码已在其它收货单入库，弹层中自动带出入库仓库、库位并锁定，见「扫码录入」。

##### 逻辑

- 空码校验：该码查不到，或已存在且全部来自采购收货可继续；存在非采购收货记录则拒绝，提示由系统返回；非空码须与已存仓库、料品一致。
- 扫码只做校验与带出，不改数据。

##### 交互

- 弹层内再扫料品码：累加到二维码数量；类型须符合订单行（规则同「扫码」）；已在弹层、校验中的重复码提示「该料品码已在本次扫描中，请勿重复扫描」；已收货的码同样先弹「扫码确认」。
- 弹层内扫 8 位货架码：带出仓库与库位编码，出现货架层数；其它非料品码提示「无法识别的二维码，请扫描料品码或8位货架码；库位请点选」。
- 点库位编码打开「选择库位」：标题「选择库位」，搜索框「搜索库位」，顶部仓库页签（物料分类与订单行一致，默认选当前用户所属部门的仓库），下方库位列表（库位编码，有备注并排显示）；点库位写回库位 / 仓库名称并关闭。仓库为车间线边库且无库位时，底部出现「确认」，点确认只记下仓库。
- 点中转仓库编码打开同样的「选择库位」，仅列物流仓库；点选写回中转仓库与库位。
- 包装单位：点开底部选项，仅列出该料品已维护的换算项（如「50kg/箱」）；仅有一项且上次未明确不使用时自动选中。选包装单位后，包装单位总量 = 每包装换算数量 × 包装单位数量，自动回写；收货总量 = 包装单位总量 × 二维码数量，自动回写。未选包装单位时，收货总量 = 手输包装单位总量 × 二维码数量。包装单位数量失焦时不大于 0 提示须大于 0。
- 点「+」打开「自定义包装单位」：见下。
- 点牌号/线径打开全屏选择页：标题「选择牌号/线径」，可搜索、下拉刷新、触底加载，每页 10 条；点选项后点「确认选择」写回，也可手输；「清空」清除。
- 弹层打开时默认带出本订单行上次保存的包装单位、数量、库位、仓库、中转、厂家批号、牌号/线径；备注不记忆。
- 仓库规则（优先级自上而下）：
  - 该码已在其它收货单入库：带出其仓库、库位（线边仓同时带出中转）并锁定不可改，点选时提示「该码已有入库仓库/库位，不可修改」「该码已有中转仓库/库位，不可修改」；与当前已锁定库位不一致时提示「该码的入库库位与当前锁定库位不一致，无法加入本次扫描」。
  - 本单已保存过的码再次扫码：自动带出上次的仓库与库位。
  - 本单已选仓库：不能换其它仓，提示「本单已选择仓库，不能更换其他仓库」；中转仓同理，提示「本单已选择中转仓库，不能更换其他中转仓库」。
  - 其余：带出上一次操作的仓库、库位；无则手选。
- 点「保存」逐项校验，不通过时提示：
  - 没有二维码：「请扫描二维码」
  - 相同二维码、厂家批号、牌号/线径已在已扫列表：「同一收货单内，相同二维码、厂家批号、牌号/线径不可重复扫描」
  - 未选库位：「请选择库位编码」；货架有层数选项未选：「请选择货架层数」
  - 入线边仓需中转未选：「请选择中转仓库/库位」
  - 选了包装单位：包装单位数量空或不大于 0：「请先填写「包装单位数量」，且须大于 0」；包装未维护换算数量：「当前包装单位未维护换算数量，无法按件收货，请更换包装或维护后再试」
  - 未选包装单位：包装单位总量空或不大于 0：「请先填写「包装单位总量（单位）」，且须大于 0」
  - 同一厂家批号已有不同生产日期：弹确认「当前厂家批次的生产日期不一致，是否全部替换为当前生产日期？」，点确定把已扫列表中该厂家批号的生产日期全部替换后继续保存，点取消不保存
- 保存成功：提示「已保存」，关闭弹层，已扫列表追加。
- 关闭弹层未保存：本次已扫但未保存的料品码按账号 + 订单行记忆，再次扫码时带回。

##### 逻辑

- 每个二维码在已扫列表生成一行；每行收货数量 = 包装单位总量（不是收货总量）。
- 唯一性：同一收货单内「二维码 + 厂家批号 + 牌号/线径」不可重复；账号 + 二维码 + 订单行用于弹层连续扫码记忆。
- 同一收货单所有行入库仓库须一致，中转仓须一致。

#### 自定义包装单位

##### 页面元素

居中弹框，一行等式：「包装单位 1 [单位名称] = [数量] 主计量单位」，底部圆形「×」。

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| 单位名称 | 文本 | 必填；提示「请输入单位名称」 |
| 数量 | 数字 | 必填；提示「请输入{主计量单位}数量」 |

按钮：保存、保存并使用。

##### 交互

- 点「保存」：新增成功后关闭弹框，包装单位选项刷新，不自动选中。
- 点「保存并使用」：同上，且自动选中新增的包装单位。
- 缺少料品信息时提示「缺少料品信息，无法保存换算单位」。

##### 逻辑

- 执行后：为当前料品新增一条包装单位换算（1 个新单位 = 数量个主计量单位），全局可用于该料品后续收货。

#### 确认收货

##### 页面元素

无字段；确认框标题「提示」，正文「确认提交收货？」。

##### 交互

- 点「确认收货」：
  - 已扫列表为空：提示「暂无数据」
  - 到货时间、入库确认时间不满足要求：提示对应文案
  - 否则弹出确认框
- 点「确定」提交：成功提示「收货提交成功」，清空已扫记录与记忆，返回采购入库列表。
- 提交一次性带上当前列表全部已扫记录，不拆分多次提交。
- 提交前再校验：存在未选仓库的记录提示「存在未关联仓库的扫码记录，请删除后重新保存」；数量无效提示「扫码记录数量或二维码无效，请检查后重试」；线边仓缺中转提示「存在未选择中转仓库/库位的扫码记录，请重新保存」。

##### 逻辑

- 可执行条件：订单行不是 ERP 已完成、不是已开立；至少有一条已扫记录。
- 校验（不通过由系统返回提示，整单不提交）：
  - 仓库须与料品分类匹配（原料入原料仓，成品入成品仓）
  - 同一批次仓库必须一致
  - 同一码多条明细的库位、中转仓、中转库位须一致
  - 同一厂家批号的生产日期须一致
  - 数量须大于 0
  - 订单行已收货数量 + 本次入库数量超过采购上限：「超过采购上限」
- 执行后：
  - 生成一个采购批次：入库批次号由系统生成；入库仓库=所选仓库；入库数量=各行收货数量之和；到货时间、入库确认时间=页面所选；入库时间=提交时间，入库人员=当前用户；入库状态=已入库；复核状态=待复核；写入本批单价快照（见《采购复核》）。
  - 每条已扫记录生成一条批次明细（二维码、仓库、库位、数量、包装单位、中转仓库/库位、厂家批号、牌号/线径、生产日期、备注），并把二维码按所选仓库库位入库。
  - 质检：料品需要质检时，明细首检状态为待质检、批次质检状态为待质检；料品免检时为免检。
  - 回写订单行：已收货数量重算、订单状态重算；首次到货日期为空则记为当天，末次到货日期记为当天。
  - 入线边仓且未跳过中转时，按所选中转仓库/库位自动生成调拨出库；跳过中转的公司或入物流仓不生成。
  - 触发库存统计等下游异步更新。
  - Web 采购批次、采购明细同步出现该批次与明细。
