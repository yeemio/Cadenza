# 采购质检模块 PRD 文档

---

## 1. 基本说明

### 1.1. 业务理解

采购质检按 **采购收货批次**（Web）与 **物料二维码**（PDA）做质检。收货时按料品是否需检写入首检记录（待质检或免检）；Web 对待质检 / 质检中批次补录仍待检码的结论，或对整批做判定合格 / 判定不合格并留下判定记录；PDA 对单个二维码逐条判定合格 / 不合格、修改结论与附件，并可对不合格的码扫码发起复检。批次质检状态随各码当前生效结论汇总。

**两端分工：**

- **Web**：按采购批次维度查询；质检 / 批量质检；判定合格 / 判定不合格；查看判定结果。
- **PDA**：采购质检列表（本篇 §3.1）：按待质检 / 合格 / 不合格 Tab 查看质检记录，逐条合格 / 不合格、修改，扫码定位；发起质检页（本篇 §3.2）：扫码多选不合格的码发起复检。

#### 质检 / 批量质检

##### 页面元素

弹窗标题：单条为「质检」，多条为「批量质检」。

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| 检验结论 | 单选 | 见字典「Web 质检结论」；打开时默认合格 |

底部：取消、确定。无备注、附件。

##### 交互

- 点操作栏「质检」打开弹窗，结论重置为合格。
- 勾选多行后点「批量质检」：仅纳入可质检且未退货的行；若无可操作行则提示先选择待质检或质检中的批次。
- 点「确定」提交；成功关闭弹窗、清空勾选、刷新列表与汇总。

##### 逻辑

- 可执行条件：批次未退货，且批次质检状态为待质检或质检中。
- 对本批次每个物料二维码，仅当当前生效质检行（有复检则复检行，否则首检行）仍为待质检时，写入所选合格/不合格；已有结论的码不改。
- 同步更新对应入库二维码质检结果；批次质检状态按码结论重新汇总。
- 本操作不写批次判定记录，不写质检备注、附件。

#### 判定合格 / 判定不合格

##### 页面元素

| 附件 | 上传 | 非必填，最多 3 个 |

底部：取消、确定。

##### 交互

- 点对应操作栏按钮打开弹窗，表单清空。
- 附件超出 3 个时提示不可再传。
- 点「确定」校验通过后提交；成功关闭弹窗并刷新列表。

##### 逻辑

- 判定合格可执行条件：批次未退货，且状态为部分合格或全部不合格。
- 判定不合格可执行条件：批次未退货，且状态为免检、全部合格或部分合格。
- 提交后：本批次每个物料二维码的当前生效质检行均置为合格（判定合格）或不合格（判定不合格）；批次质检状态变为全部合格或全部不合格。
- 写入或覆盖本批次判定记录（同一批次仅一条，新覆盖旧）：判定人、判定时间、结论、备注、附件。
- 同步更新对应入库二维码质检结果。

| 上传附件 | 图片上传 | 非必填；最多三张；上传格「最多三张」 |

##### 交互

- 点「合格」「不合格」「修改」打开弹框，附件为空。

- 修改时单选未选中：提示「请填写质检结果」。

- 可执行条件：二维码所在批次未退货；免检的码不可提交；首检记录若已有复检记录则不可再提交，须操作复检记录。
- 执行后本模块：该条质检记录结论更新为合格或不合格，记下质检人员、质检时间、附件；该二维码质检结果同步更新；批次质检状态按各码当前生效结论重新汇总。
- 合格、不合格可反复提交，后一次覆盖前一次。
- 不写质检备注。

  - 其它码：提示「请扫描正确的二维码」

#### 提交质检

##### 页面元素

确认框，标题「提交质检」，正文「确认发起质检？」，按钮：取消、确定。

##### 交互

- 点「提交质检」：
  - 列表为空：提示「请扫描物料二维码」
  - 没有选中卡片：提示「请选择要提交质检的记录」
  - 否则弹出确认框
- 点「确定」：把选中的全部卡片一次提交；成功提示「已提交」，稍后回到采购质检页；失败提示系统返回的原因，列表保留。

##### 逻辑

- 可执行条件：所选「二维码 + 批次」未退货；已有质检记录时，当前生效结论须为不合格且尚无复检（复检至多一次）；无质检记录的码补一条首检。
- 同一「二维码 + 批次」重复提交按一条处理；任一条不满足则整单失败，不部分提交。
- 执行后：
