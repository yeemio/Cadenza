## 1. 基本说明

### 1.1. 业务理解

实绩录入是车间操作工在 PDA 上对生产订单做「开工、产出报工、投料」的主入口。操作工从主页「实绩录入」进入生产订单列表，选中订单进入订单工作台，再按需进入「生产实绩录入」（报工）或「生产投料」（单独投料）。报工时扫载具码录入每一轴产出，产出先保存为未提交的报工单，确认无误后「提交报工」形成正式报工记录。投料只通过订单工作台「生产投料」单独提交，报工详情不录投料。

一张报工单从操作工保存第一条产出开始生成，状态为 **未提交**；提交后变为 **已提交**。自动审核以订单的 **末道非质检工序** 为准（末道为质检工序时，往前取最近一道非质检工序；全部为质检工序时不自动审核）：报该工序以外的工序，提交后自动审核通过；报该工序时，只有该工序所属车间在「末道自动审核车间」配置中才自动审核通过，否则为 **待审核**，由有权限的人在 Web 或 PDA「报工记录」审核。物流报工（选中物流工序，或从主页「物流」菜单进入）保存产出时即为审核通过，提交时生成入库单，不执行审核通过后的回写。

```text
主页「实绩录入」
  └─ 生产订单列表（可侧键扫设备码筛出该设备排产订单，允许开工的订单可直接「开工」）
        └─ 订单工作台
              ├─ 生产实绩录入 → 报工详情
              │     ├─ 选工序 → 扫载具码录产出（保存即生成「未提交」报工单）
              │     └─ 提交报工 → 已提交
              │            ├─ 非末道非质检工序 / 末道非质检工序且车间在自动审核配置中 / 物流报工 → 审核通过
              │            └─ 其余 → 待审核（报工记录中审核）
              ├─ 生产投料 → 单独投料（扫码后直接提交并扣减库存）
              └─ 工时录入（未开放）
```

**两端分工：**

- **PDA**：开工、扫码报工、单独投料都在 PDA 完成。主页另有「N条报工待提交」入口，直接回到自己未提交的报工单。
- **Web**：「生产订单」可开工、批量开工、订单报工、查看生产进度（「报工」「批量报工」已停用，界面保留）；报工结果在「报工记录」查看、审核、取消审核（见《04-报工记录》第 2 章）；投料结果在「投料记录」查看（见《05-单独投料》第 2 章）。

##### 交互

- 生产状态着色见字典「生产状态」。
- 缺少分段信息的行底色 `#FFF9C4`。
- 鼠标悬停生产进度，浮层显示每道工序的工序名称、下线数量、已完成数量、进度。
- 生产进度 = 各工序（下线数量 > 0）进度的平均值；工序进度 = 工序已完成数量 ÷ 下线数量；百分比向下取整，最大 100%。工序未配置时为 0。
- 搜索条件和分页需记忆：页签未关闭时离开再回来保留上次条件；关闭页签后清空。
- 点「重置」：生产状态清空（查全部状态），生产部门恢复为当前用户部门，其余条件清空。
- 行可勾选；批量开工、导出按勾选行执行。
- 导出：勾选时确认框「确定导出选择的数据」，导出勾选行；未勾选时确认框「确定导出所有的数据」，导出全部订单（不受搜索条件限制）。
- 操作栏按钮显隐：
  - 开工：仅允许开工显示
  - 订单报工：仅进行中显示
  - 工序设置：已结束不显示
  - 查看：始终显示
  - 报工：进行中且工序已配置时显示（已停用，点击提示「功能已停用」）
  - 风险评估：计划完工时间距今 ≤ 7 天（含已逾期）且生产状态不是已结束时显示
  - 设备排产：未结束且工序已配置时显示

##### 逻辑

- 工序未配置的订单，PDA 进入订单时提示「请先在电脑端配置工序」。
- 订单已有报工（含未提交的报工单）后，工序设置中不能新增、删除、调整顺序或更换工序；工序备注、芯倍数、绞合系数、下线数量仍可修改。

##### 交互

按扫到的码类型依次判断：

- **扫码删除弹层打开中**：按「扫码删除」处理。
- **设备码**：
  - 未选工序：「请选择工序」
  - 工序没有工作中心：「当前工序缺少工作中心信息，无法校验设备」
  - 设备码格式不对：「设备码格式无效，请重新扫描」

- **手动报工模式下扫非托码**：「手动上报模式下，不可以扫描成品码」。

- **本单已有手动报工产出（非手动报工模式）**：扫任何码均提示「手动上报模式下，不可以扫描成品码」。
- **非割线分盘工序扫托码**：「非割线工序不能扫描托码」。
- **物流入口**：不校验工序，直接按产品轴码处理。
- **未选可开工工序**：「请选择工序」。
- **割线分盘工序**：
  - 还没有托码时扫托码：托盘上已有产出则先确认（见「托码绑定」），否则提示「绑托成功」并打开产出录入弹层。
  - 已有托码再扫另一个托码：弹出「确认修改托码」（见「托码绑定」）。
  - 产出录入弹层中，扫码写入当前高亮的字段（托码或扫码数量）；同一个码不能既做托码又做产品轴码，分别提示「该二维码已作为托码，不能重复使用」「该二维码已录入，请勿重复扫描」；码类型不对提示「请扫描正确的托码或二维码」。
- **产品轴码**：
  - 校验通过：打开产出录入弹层。
  - 载具上已录过产出：弹出载具已录入确认（见「载具已录入确认」）。
  - 托码：提示「托码已录入」。

- 产品轴码不允许装入的情况（后端提示原文）：
  - 本次报工已录过该轴：「此次报工已经录入过该轴」
  - 该轴在本订单已有完成的质检：「该码存在关联该订单的已完成的质检记录,无法再次报工」

  - 报工工序是末道非质检工序：该工序生产部门在「末道自动审核车间」配置中时自动审核通过，否则待审核。
- 自动审核通过后：产出转入所选仓库，回写订单已完成数量、排产完成数量，发起成品质检，写工时日志；末道工序且订单类型不是样品订单时推送 ERP。

#### 扫码投料

##### 页面元素

- 不允许投料的情况（后端提示原文）：
  - 订单或工序有误：「订单工序ID不能为空」「订单工序不存在」「订单与工序不匹配」「订单不存在」
  - 托码：「投料扫描不支持托码」

  - 码缺销售单号或行号：「投料码档案销售订单号或行号不能为空」
  - 未审批或未质检完成：「二维码未审批或未质检完成」
  - 不在库：「二维码状态错误」
  - 码所在仓库不存在：「二维码仓库不存在」
  - 不在线边库：「二维码必须存在于线边库」
  - 成品 / 原料：「成品不可消耗」/「原料不可消耗」
  - 本工序产出：「该码为当前工序产出，不可作为投料」
  - 本订单半成品但不是投料工序之前任一工序的产出：「只可以消耗前道工序的产出」；找不到前道工序：「未查到前道工序」
  - 可投数量为 0：「可投数量不足」
- 前道工序指本订单内排在投料工序之前的任一工序，不限于紧邻的上一道。
- 同一码对应多个销售行时：不符合工序规则的销售行不显示；任一销售行可投数量为 0 时整码提示「可投数量不足」。
- 扫码只做校验和试算，不扣减。

##### 交互

- 前端校验：
  - 未选工序：「请选择工序」
  - 列表为空：「请先扫码添加投料数据」
  - 某行不大于 0：「第{行号}行本次投料需大于0」
  - 缺订单：「缺少订单信息，无法投料」
- 提交中再次点击无效。
- 成功提示「提交成功」，清空列表、工序和本机暂存，回订单工作台。
- 失败提示后端原文，无原文时提示「投料提交失败」，留在本页：
  - 「投料码不能为空」「订单不能为空」「订单工序ID不能为空」
  - 「订单工序不存在」「订单与工序不匹配」
  - 「投料码档案销售订单号或行号不能为空」「本次投料数量必须大于0」
  - 「投料码不存在或未在二维码档案中」
  - 「二维码总消耗数量超出了当前二维码数量」
  - 「轴上物料已被消耗或二维码不存在,余量不足,无法进行减少库存的操作」
  - 托码、质检、在库、线边库、成品 / 原料、前道工序的校验提示（同「扫码投料」）

##### 逻辑

- 可执行条件：工序属于本订单；重新校验托码、码存在、销售单号行号、质检、在线边库在库、成品原料、前道工序（本工序产出在提交时提示「只可以消耗前道工序的产出」）；按销售行汇总的本次投料不超过该码剩余数量。
- 执行后：
  - 按销售行扣减投料码剩余数量，扣到 0 的码档案删除。
  - 写入投料记录：投料类型为单独投料，同一次提交为一个批次；投料物料、仓库等从码档案带入；记录投料前数量、投料数量、投料后数量、发料仓库、投料工序、投料人、投料时间。
  - 写 SAP 投料日志，发送库存变动消息。
