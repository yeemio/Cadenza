# 报工记录模块 PRD 文档

---

## 待确认 / 已知问题

1. Web「删除」按钮只判断权限，不判断提交状态、审核状态，点击后由后端拦截；需确认是否按状态隐藏。
2. PDA「累计报工」统计未区分提交状态、审核状态，也不排除历史导入，生产单号为模糊匹配；会把未提交报工单的产出也算进去，而列表只显示已提交的报工单，两者可能对不上。本文暂按现状编写。
3. PDA「累计报工」单位固定按「米」显示，非米单位的订单会显示错误单位。
4. Web 编辑模式下产出数量改为 0 的行会被删除，但页面没有提示，需确认是否需要提示。
5. 「已入库」统一按「任一产出码已入库就拦截」编写；现有代码编辑、取消审核只在产出码全部入库时才拦截（「存在已入仓库的码,无法撤销」），部分入库时仍可执行，需开发修改。删除已是任一码入库即拦截。
6. Web 编辑提交时，后端把生产人员改为当前用户、开工时间改为订单实际开工时间、完工时间改为当前时间并重算生产时长；本文按「以界面选择的生产人员为准，开工 / 完工时间不变」编写。
7. Web 审核通过失败时，会先弹后端原文，再弹「审核失败，请重试」，两条提示都会出现。
8. Web 编辑按钮、详情页工序置灰按「报工单创建部门 = 当前用户部门」整串比较，多部门用户永远看不到「编辑」。
9. Web 详情「段长」列的显示条件写成恒为真：只要首行没有客户轴号就显示「段长」列；两列都只按首行判断。本文按「有客户轴号 / 只有段长时显示」编写。
10. Web 编辑无产出的报工单直接改产出数量时，只更新报工单本身，不重算工序完成数量、订单已完成数量、排产完成数量。
11. 「是否需要审核」为空的历史报工单删除时后端空指针，返回系统错误。
12. PDA 报工明细详情的「托盘编码」只汇总已加载的产出分页，上拉加载后可能变多。
13. 主页扫托码「审核通过」按钮按「托上有审核状态为待审核的报工单」显示，未提交的报工单审核状态也是待审核，所以只有未提交单时按钮也会显示，点击才提示「请先提交相关报工」。
14. Web 详情「生产工序」是复选框组，编辑时可勾选多道工序，但报工单只能存一道工序。

## 1. 基本说明

### 1.1. 业务理解

报工记录汇总「实绩录入」「工作台报工」「扫码报工」三个入口提交的报工单，供班组长、车间主任查看、审核、修正。

- **审核**：需要人工审核的报工单（报订单的末道非质检工序、且该工序所属车间不在「末道自动审核车间」配置中；末道为质检工序时往前取最近一道非质检工序）提交后为 **待审核**（工序完成数量在提交时即重算，不看审核状态），审核通过后产出才入库、计入订单已完成数量和排产完成数量、发起成品质检。
- **取消审核**：把人工审核通过的报工单退回待审核，同时撤回入库、完成数量、质检。产出已入仓库、码已被后续工序改动、已有质检完成时不能撤销。
- **编辑**：只修改报工单的工序、生产人员、产出数量，不改变审核状态；已审核通过的人工审核单不能编辑。
- **删除**：删除报工单及其产出码、报工投料记录，回退完成数量；人工审核通过后不能删除。

```text
PDA 提交报工
  ├─ 自动审核（物流报工 / 非末道非质检工序 / 末道非质检工序且车间在自动审核配置中）→ 审核通过
  └─ 需要人工审核 → 待审核
        ├─ Web「审核」/「批量审核」、PDA「审核通过」、PDA 主页扫托码「审核通过」→ 审核通过
        │     └─ Web「取消审核」→ 待审核
        ├─ Web「编辑」（不改变审核状态）
        └─ Web「删除」
```

**两端分工：**

- **Web**：报工记录列表、审核、批量审核、取消审核、编辑、删除、导出。
- **PDA**：报工明细列表、累计报工汇总、报工明细详情、审核通过。

##### 交互

- 汇总行按勾选行实时计算：报工总量按生产单位分别求和，保留 4 位小数，未选时显示 0；报工总轴数为勾选行报工轴数之和。
- 操作列按钮显隐：

| 按钮 | 显示条件 |
| ---- | ---- |
| 审核 | 已提交、待审核、非物流报工 |
| 查看 | 始终显示 |
| 编辑 | 已提交、（待审核或无需审核）、报工单创建部门为当前用户所属部门 |
| 删除 | 始终显示 |
| 取消审核 | 已提交、审核通过、需要审核、非物流报工 |

- 点「审核」「查看」「编辑」进入报工详情页面（见 2.2），分别为审核、查看、编辑模式。
- 从报工详情返回本页时自动刷新列表。
- 点「重置」清空全部搜索条件（含默认的提交状态和生产部门）；重置后不按部门过滤，可看到全部部门的报工（操作工限制仍生效）。

##### 逻辑

- 数据范围：所选生产部门及其下级部门；当前用户只有「操作工」一个角色时只看自己参与的报工。
- 排除历史导入的报工记录；不显示产出数量为 0 的报工单。
- 默认排序：待审核在前、审核通过在后，再按创建时间倒序。

#### 批量审核

##### 页面元素

无

##### 交互

- 未勾选：提示「请选择至少一条数据」。
- 确认框标题「提示」，内容「确定完成审核?」，按钮「确定」「取消」。
- 成功提示「操作成功!」并刷新列表；任一条失败则整批不生效，提示后端原文：
  - 「报工单不存在」
  - 「存在没有提交无法审核」
  - 「状态不对,存在报工单已审核通过」
  - 「报工数量超额部分超出了规定的超额比例」

##### 逻辑

- 逐条审核所选报工单，同 2.2「审核通过」。

#### 导出

##### 页面元素

无

##### 交互

- 确认框标题「提示」，内容「确定导出选择的数据」，按钮「确定」「取消」；确认后下载「报工记录.xlsx」。
- 有勾选时只导出勾选行；未勾选时按当前搜索条件导出全部（「行号」条件不生效，不做「操作工只看自己」的限制）。

##### 逻辑

- 导出列：生产单号、生产工序、料品名称、报工数量、英尺（表头为「英尺」）、报工轴数、客户轴号、报工仓库、颜色、规格、报工日期、生产部门、生产人员、审核状态、是否需要审核、生产时长、备注、提交状态。

#### 删除

##### 页面元素

无

##### 交互

- 确认框标题「提示」，内容「确定将选择数据删除?」，按钮「确定」「取消」；确认后提示「操作成功!」并刷新列表。
- 不允许时提示后端原文：
  - 「轴码已变更,无法修改,请先撤销后续步骤」
  - 「二维码已入库」
  - 「需要审核的记录,在审核通过后,无法删除!」

##### 逻辑

- 可执行条件：报工单有产出码（无产出码时提示「轴码已变更,无法修改,请先撤销后续步骤」）；产出码未被后续工序改动（码数量与产出一致）、产出码均未入库；需要审核的报工单须为待审核。
- 执行后：
  - 删除报工单及其工序、人员、产出、产出码、报工投料记录、工时日志。
  - 无需审核（已自动审核通过）的报工单，同时扣回产出库存、撤回成品质检。
  - 重算工序完成数量、订单已完成数量，扣回排产完成数量。

#### 取消审核

##### 页面元素

无

##### 交互

- 点击直接执行，无二次确认；成功提示「操作成功!」并刷新列表。
- 不允许时提示后端原文：
  - 「状态不对,报工单未审核通过」
  - 「轴上物料已被消耗或二维码不存在,余量不足,无法进行减少库存的操作」
  - 「存在已入仓库的码,无法撤销」
  - 「码数据有变更,无法撤销」
  - 「存在质检完成的产出,需要先撤销质检」

##### 逻辑

- 可执行条件：审核通过；产出码存在、均未入仓库、数量未变更；需要质检的码对应质检单都还在质检中。
- 执行后：
  - 产出出库（撤回线边库库存）。
  - 重算工序完成数量、订单已完成数量，扣回排产完成数量。
  - 撤回成品质检，恢复码的质检状态。
  - 审核状态改为待审核，清空审核人、审核时间。

- 产出明细类型见字典「产出明细类型」。

#### 审核通过

##### 页面元素

审核模式「通过」按钮。

##### 交互

- 确认框，标题「报工审核」，内容「确定要通过此报工记录吗？」，按钮「确定」「取消」。
- 成功提示「操作成功!」，回报工记录；失败提示后端原文，无原文时提示「审核失败，请重试」：
  - 「报工单不存在」
  - 「存在没有提交无法审核」
  - 「状态不对,存在报工单已审核通过」
  - 「报工数量超额部分超出了规定的超额比例」（末道工序累计报工超过生产数量 × 超额系数）

##### 逻辑

- 可执行条件：报工单已提交、待审核。
- 执行后：
  - 审核状态改为审核通过，记录审核人、审核时间。
  - 产出转入报工仓库。
  - 重算工序完成数量、订单已完成数量，计入排产完成数量。
  - 发起成品质检，更新码的质检状态。
  - 写工时日志。
  - 末道工序（非样品订单类型）推送 ERP；末道非质检工序额外推送上架任务。

#### 编辑提交

##### 页面元素

编辑模式「确定」按钮。

##### 交互

- 前端校验：
  - 未选工序：「请选择生产工序！」
  - 未选生产人员：「请选择生产人员！」
  - 产出数量为空或不大于 0：「产出数量不能为空或零，请填写有效的产出数量！」
- 成功提示「操作成功!」，回报工记录；失败提示后端原文，留在本页：
  - 「订单已挂起,无法报工」「订单不处于可以报工的状态」
  - 「报工数量超额部分超出了规定的超额比例」
  - 「需要审核的记录,在审核通过后,无法修改」
  - 「有产出时,无法修改工序」
  - 「存在质检完成的产出,需要先撤销质检」
  - 「轴码已变更,无法修改,请先撤销后续步骤」
  - 「存在已入仓库的码,无法撤销」

##### 逻辑

- 可执行条件：订单未挂起、生产状态为进行中；需要审核的报工单须为待审核；末道工序不超额；有产出时工序不能变、需要质检的码对应质检单都还在质检中、码未被后续工序改动、产出码均未入库。
- 执行后：
  - 更新工序、生产人员、产出数量，审核状态不变。
  - 产出明细中改过数量的行：更新数量和库存；数量改为 0 的行视为删除该产出。
  - 有数量变动时：重算报工单产出数量、工序完成数量、订单已完成数量、排产完成数量，并按新数量更新成品质检。
  - 同步更新上架任务；编辑不推送 ERP。

#### 批量修改数量

##### 页面元素

点「批量修改」打开弹窗，宽 500px，标题「批量修改数量」，点遮罩不关闭。

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| *修改数量 | 数字 | 最多 4 位小数，不小于 0；提示「请输入产出数量」 |

按钮：「取消」「保 存」。

##### 交互

- 未填数量点「保 存」：提示「请输入修改数量」。
- 保存后所勾选行的数量统一改为该值，提示「操作成功!」，关闭弹窗并清空勾选，产出数量重算。

##### 逻辑

- 只修改页面数据，点「确定」提交后才生效。
