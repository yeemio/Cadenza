# 单独投料模块 PRD 文档

---

## 待确认 / 已知问题

1. 单独投料选择投料工序时不校验工序是否可开工、是否属于本部门，与报工详情选工序规则不一致，需确认是否补齐。
2. 本订单只有一道工序且为质检工序时，现有代码也会直接选中并允许扫码；本文按「仅非质检工序才自动选中」编写。
3. 单独投料提交后，后端发送的库存变动消息查的是报工产出表，不包含投料码，库存统计实际不刷新；本文按「发送库存变动消息」编写，需后端修复。
4. 投料记录的投料前数量、投料后数量取 PDA 扫码时的剩余数量，后端提交时不按实时余量重算；扫码后余量有变化时记录会不准（扣减和余量校验是实时的）。
5. Web 投料记录列表不区分投料类型（报工投料 / 单独投料），建议增加「投料类型」列和搜索条件。
6. Web 投料记录「生产部门」按订单生产部门精确匹配，不包含下级部门，与报工记录（含下级部门）不一致。
7. Web 投料记录「产品轴号」搜索按批次号匹配，批次号为空的历史投料行搜不到。

---

## 1. 基本说明

### 1.1. 业务理解

单独投料用于在 **不报工** 的情况下记录订单某道工序消耗的前道半成品（中转轴）。操作工在订单工作台点「生产投料」，选择投料工序，扫中转轴上的产品轴码，填写本次投料长度后提交，系统立即扣减该码的剩余数量，并写入投料记录。

与报工投料的区别：

- **报工投料**：随报工一起提交扣减，投料记录挂在该报工单下。PDA 报工详情已不再录入投料，Web「投料记录」中的报工投料均为历史数据。
- **单独投料**：提交即扣减，不依附报工单，同一次提交的多条投料记为一个批次。

投料只允许消耗：已质检、在线边库、有剩余数量的半成品码；本订单的半成品必须是投料工序前道工序的产出；其它订单的半成品需操作工确认后才能投。

```text
订单工作台「生产投料」
  └─ 单独投料页：选投料工序 → 扫产品轴码（逐条校验、试算剩余）→ 填本次投料
        └─ 确定 → 扣减码剩余数量 → 写投料记录（单独投料，一批）→ 同步 SAP 投料日志、库存
              └─ Web「投料记录」按批次查看
```

**两端分工：**

- **PDA**：单独投料录入与提交。
- **Web**：投料记录查询、查看批次明细（同时包含报工投料和单独投料）。

### 1.2. 字典说明

#### 投料类型

| 类型值 / 状态值 | 说明 | 颜色 |

| 类型值 / 状态值 | 说明 | 颜色 |
| --------------- | ---- | ---- |
| 托码 | 10 位载具码，第 2 位为 `P`，不能投料。 | |

| 原料码 | 10 位载具码，第 2 位为 `R`，不能投料。 | |

## 3. PDA 端

> 字典见 1.2。
>
> 真机用 PDA 侧边扫码键扫码；设计图在页面放「扫码」按钮，点它完成本次扫码。扫码成功、失败分别播放成功音、失败音。
>
> 导航栏左侧「BACK」。PDA 物理返回键被拦截。

### 3.1. 单独投料页面

**入口：**订单工作台「生产投料」。订单工作台可从「实绩录入」（生产订单列表点订单）或「工作台」（工作台详情点订单）进入，两种入口仅默认工序和本机暂存不同，其余功能一致。

#### 列表页面

##### 页面元素

**导航栏标题：**生产订单

**投料工序栏：**本订单有工序时显示。左侧蓝字「投料工序：」，右侧本订单工序标签，文字为「工序名(工序备注)」，无备注只显示工序名，可换行。本订单无工序时不显示该栏。

**提示行：**「投料数量」+ 红字「（请使用侧边按钮扫码投料）」。

**卡片展示字段：**

| 字段 | 说明 |
| ---- | ---- |
| 产品轴号 | 有客户轴号显示客户轴号，否则显示二维码；非本订单半成品时，标签「产品轴号：」后紧跟红字「（非本订单半成品）」 |
| 销售单号 | 该码的销售单号 |
| 生产单号 | 该码所属生产单 |
| 物料名称 | |
| 规格 | |
| 颜色 | |
| 中转轴剩余数量（米） | 加粗 |
| 本次投料（米） | 数字输入 |

**卡片上的按钮：**卡片右侧「×」删除本行。

**页面按钮：**底部贴边整宽「确定」。

##### 交互

- 投料工序着色见字典「投料工序标签状态」；点质检工序无反应。
- 单选，再点已选中的工序取消选中；已有投料行时不能切换，提示「已录入投料数据，无法切换工序」。
- 默认工序：
  - 从工作台进入：本订单在工作台入口选过工序时取上次的；否则取工作台所选工序；该工序不在本订单或为质检工序时，取第一个非质检工序。
  - 从实绩录入进入：本订单在实绩录入入口选过工序时取上次的；否则取第一个非质检工序。
  - 本订单只有一道工序且为非质检工序时直接选中。
- 本次投料只能输入数字，最多 4 位小数；超过剩余数量时自动改为剩余数量，并提示「第{行号}行本次投料不能大于剩余数量」。
- 点「×」直接删除本行，不二次确认；删光后可重新切换工序。
- 点 BACK 暂存后回订单工作台。

##### 逻辑

- 未提交的投料行和所选工序按「订单 + 入口（实绩录入 / 工作台）」暂存在本机，不区分用户，不过期。
- 进入时先恢复本入口暂存的投料行；本入口没有投料行时，恢复另一入口未提交的投料行和工序；只有工序选择、没有投料行的记忆不跨入口。
- 提交成功后清除本订单两个入口的暂存。

#### 扫码投料

##### 页面元素

页面「扫码」按钮（设计图）。

##### 交互

- 依次校验：
  - 码格式：只接受产品轴码（10 位载具码，第 2 位为 `E` / `F` / `M`）；托码、原料码或格式不符提示「请扫描有效产品轴码」。
  - 缺订单：「缺少订单信息，无法投料」。
  - 未选工序：「请选择工序」。
- 扫码成功追加到列表，本次投料默认等于剩余数量；同一码按销售单号 + 行号拆成多张卡片。
- 同一码同一销售行重复扫码：覆盖为最新剩余，本次投料取原填写值与新剩余中较小的一个。
- 码属于其它订单的半成品时，先弹出「非本订单半成品确认」。
- 查不到：「未找到该投料记录」（后端无可投结果时通常直接提示「可投数量不足」）；网络异常：「扫码投料失败」；其它失败提示后端原文。
- 提示音：成功播放成功音；失败播放失败音，但「未找到该投料记录」「扫码投料失败」和弹出非本订单确认框时不播放。

##### 逻辑

- 不允许投料的情况（后端提示原文）：
  - 订单或工序有误：「订单工序ID不能为空」「订单工序不存在」「订单与工序不匹配」「订单不存在」
  - 托码：「投料扫描不支持托码」
  - 码不存在：「投料码不存在或未在二维码档案中」
  - 码缺销售单号或行号：「投料码档案销售订单号或行号不能为空」
  - 未审批或未质检完成：「二维码未审批或未质检完成」
  - 不在库：「二维码状态错误」
  - 码所在仓库不存在：「二维码仓库不存在」
  - 不在线边库：「二维码必须存在于线边库」
  - 成品 / 原料：「成品不可消耗」/「原料不可消耗」
  - 本工序产出：「该码为当前工序产出，不可作为投料」
  - 本订单半成品但不是投料工序之前任一工序的产出：「只可以消耗前道工序的产出」；找不到前道工序：「未查到前道工序」
  - 可投数量为 0：「可投数量不足」
- 前道工序指本订单内排在投料工序之前的任一工序，不限于紧邻的上一道。
- 同一码对应多个销售行时：不符合工序规则的销售行不显示；任一销售行可投数量为 0 时整码提示「可投数量不足」。
- 扫码只做校验和试算，不扣减。

#### 非本订单半成品确认

##### 页面元素

居中确认框，内容「当前扫码物料存在非本订单的半成品，确定要继续投料吗？」。按钮：左红色「取消」，右蓝色「确定」。点遮罩不关闭。

##### 交互

- 点「确定」追加到列表并标记「（非本订单半成品）」；点「取消」放弃本次扫码。
- 弹窗打开期间新的扫码不处理。

##### 逻辑

无

#### 确定提交

##### 页面元素

无

##### 交互

- 前端校验：
  - 未选工序：「请选择工序」
  - 列表为空：「请先扫码添加投料数据」
  - 某行不大于 0：「第{行号}行本次投料需大于0」
  - 缺订单：「缺少订单信息，无法投料」
- 提交中再次点击无效。
- 成功提示「提交成功」，清空列表、工序和本机暂存，回订单工作台。
- 失败提示后端原文，无原文时提示「投料提交失败」，留在本页：
  - 「投料码不能为空」「订单不能为空」「订单工序ID不能为空」
  - 「订单工序不存在」「订单与工序不匹配」
  - 「投料码档案销售订单号或行号不能为空」「本次投料数量必须大于0」
  - 「投料码不存在或未在二维码档案中」
  - 「二维码总消耗数量超出了当前二维码数量」
  - 「轴上物料已被消耗或二维码不存在,余量不足,无法进行减少库存的操作」
  - 托码、质检、在库、线边库、成品 / 原料、前道工序的校验提示（同「扫码投料」）

##### 逻辑

- 可执行条件：工序属于本订单；重新校验托码、码存在、销售单号行号、质检、在线边库在库、成品原料、前道工序（本工序产出在提交时提示「只可以消耗前道工序的产出」）；按销售行汇总的本次投料不超过该码剩余数量。
- 执行后：
  - 按销售行扣减投料码剩余数量，扣到 0 的码档案删除。
  - 写入投料记录：投料类型为单独投料，同一次提交为一个批次；投料物料、仓库等从码档案带入；记录投料前数量、投料数量、投料后数量、发料仓库、投料工序、投料人、投料时间。
  - 写 SAP 投料日志，发送库存变动消息。
