# 【模块名称】模块 PRD 文档

---

> **【模板用途｜勿写入具体业务 PRD｜主题构想】**
>
> 本 PRD 按「模块整体 → 字典 → Web 页面 → PDA 页面」组织：
>
> | 章节 | 写什么 | 谁看 |
> | ---- | ------ | ---- |
> | **1.1 业务理解** | 对本模块的整体描述 | 产品 / 开发 / 测试入门 |
> | **1.2 字典说明** | 本模块用到的全部业务字典（Web 与 PDA 共用，不按端拆开） | 产品 / 开发 / 测试 |
> | **2 Web 端** | 按 **页面** 写；一个 `###` 对应一个页面；从入口点进的全新二级页另起 `### 2.2` | 见下 |
> | **3 PDA 端** | 结构同 Web；按 PDA 的卡片列表、查询、扫码、整页跳转来写 | 见第 3 章 |
>
> **Web 端按「页面」拆 `###`：**
>
> ```text
> ## 2. Web 端
> ├── ### 2.1 某某管理页面          ← 入口页（列表 + 本页弹窗类功能）
> │     ├── #### 列表页面
> │     ├── #### 导入 / 删除 …
> │     └── …
> └── ### 2.2 某某明细/清单页面    ← 从 2.1 点进去的全新页（自带工具栏、操作栏等）
>       ├── #### 列表页面
>       ├── #### 选择物料 / 编辑 …
>       └── …
> ```
>
> **何时写 `### 2.2`（及 2.3…）：**  
> 本页某个功能打开后是 **全新页面**（独立 Tab/路由），且该页自己还有列表、上方按钮、操作栏等一整套功能 → **不要**塞在 `2.1` 的某个 `####` 里写完，应另起 `### 2.2`（如《物料校验》的「物料清单」）。  
> 若只是弹窗（新增/编辑/审批等）→ 仍写在当前 `###` 下的 `####` 功能点即可。
>
> **一个页面（如 `### 2.1`）下面写什么：**
>
> ```text
> ### 2.1 供应商页面
> ├── #### 列表页面          ← 有列表才写
> ├── #### 新增/编辑         ← 基本一样则写一起
> ├── #### 删除/批量删除     ← 单独与批量一致则写一起
> └── …                     ← 有几个写几节；页面展示差别大则分开
> ```
>
> **每一个 `####`（列表或任一功能点）都是同一套三维结构，不增不减：**
>
> | 小节 | 写什么 | 谁看 |
> | ---- | ------ | ---- |
> | **页面元素** | 对照设计图：有哪些控件、列、字段 | **设计/产品对照稿；开发、测试可不看** |
> | **交互** | 怎么表现、怎么操作 | **开发、测试看** |
> | **逻辑** | 允不允许、执行后本模块/关联模块如何变 | **开发、测试看** |
>
> **状态流转、与他模块关联** 写在对应功能的「交互」「逻辑」里，不另开章。  
> **无内容**：该节留空或写「无」。  
> **不写**：接口、编码、库字段、菜单权限；常规取消/确定等默认交互。  
> **PDA** 与 Web 共用第 1 章；页面写法见 **第 3 章**（三维相同，列表改卡片，并补查询、扫码、下拉/上拉）。

## 2. Web 端

### 2.1. 【页面名称，如：供应商页面】

> **【模板用途｜勿写入具体业务 PRD】**  
> 本 `###` = **一个页面**。其下：
>
> 1. **有列表** → 先写 `#### 列表页面`；无列表则跳过。  
> 2. **功能点** → 本页实际有几个就写几个 `####`；没有的不写。  
> 3. **每一节三维相同**：`##### 页面元素` → `##### 交互` → `##### 逻辑`。  
> 4. **功能点合并**：新增/编辑基本一样 → 写成「新增/编辑」；单独操作与批量操作一致（如删除与批量删除）→ 写成「删除/批量删除」；**页面展示差别大** → 分开写。  
> 5. **打开后是全新页**（如点「物料清单」进入二级 Tab，该页自有按钮与功能）→ 另写 `### 2.2`，结构与本页相同；入口页交互只写「跳转到 2.2」，不在本页展开二级页全部功能。
>
> 以下「交互」「逻辑」条目适用于 **每一个** `####`，按需选用；可继续追加。  
> **写法提示**：每条先写规则；需要参考时看规则下的「例：」（仅模板参考，**勿原样抄进业务 PRD**）。多数例文写完整可落库的句子即可；**操作栏按钮显隐/置灰**等条目若条件多，用嵌套无序列表按项分行写。
>
> **交互**（开发、测试看。与通用后台默认不一致时才写）：
>
> - 搜索条件或表单内 **联动 / 置灰**（选 A 后 B 选项变化、某区出现/消失等）  
>   - **简单联动**：直接写清条件与结果。  
>     例：工作令号与设备名称联动；未选工作令时，设备名称置灰不可选。  
>   - **复杂联动**：只点明存在哪些字段/区域联动，**细则以设计图为准**，不必在 PRD 展开全部分支。  
>     例：物料分类、计价单位、下料尺寸形式联动显隐原材料相关字段（细则以设计图为准）。
>
> - 操作栏按钮的 **显隐 / 置灰**（随业务状态等变化）；**列表上方按钮的显隐/置灰无需写**。按钮较多时：交互里先写一句总述，再在其下用**嵌套无序列表**，**一行一个按钮**写清显隐或置灰条件，避免挤成一段长文  
>   例：
>
>   - 操作栏按钮显隐和置灰：
>     - 跟进采购：待采购、采购中显示；已完成不显示
>     - 撤销确认：仅待确认显示
>     - 删除：仅待采购且未软占用时可点；已下单或软占用中置灰
>
> - 行或字段 **底色 / 高亮/加粗**（非字典状态色的特殊行底色等写明颜色；颜色已在字典中则写「见字典××」即可，不重复列色）  
>   例：申请状态着色见字典「申请状态」
>
>   例：申请采购数量、入库数量以蓝色加粗显示；待采购数量以橙色加粗显示；
>
> - 点击某字段后 **跳转** 到其它页/详情（非默认弹窗）  
>   例：点击采购收货进度，跳转采购收货并带入关联采购订单号。
>
> - 点击数据行可勾选 / 取消  
>   例：点击数据行可勾选或取消勾选。
>
> - 列表 **排序** 说明  
>   例：按创建时间倒序。
>
> - 列表有 **固定列**  
>   例：第一列销售订单号固定,左右轮滑固定列不变。
>
> - 列表上 **进度条或数字** 的说明（**分子 / 分母如何计写在此处**，不写进下方逻辑「数据范围 / 汇总规则」）  
>   例：核查进度 20/50；分子 = 该分组已核查行数，分母 = 该分组核查总行数。
>
>   例:   待采购数量=需求数量-已申请采购数量
>   
> - 新增页若有子数据，须说明子数据是否必须存在  
>   例：新增时至少保留 1 条采购明细，不允许空明细保存。
>
> - 列表 / 详情无值显示 `-`：**不是默认规则**。仅当设计图画出空态为 `-`，或产品在本文明确写出时才写；适用字段合并写在同一行，不要逐字段多行。设计图未画、产品未写 → **整条不写**  
>   例：计划开始日期、计划完成日期、实际完成日期无值显示 `-`。
>
> - **编辑页特殊字段取值 / 联动计算**（参考电气件核查「编辑核查内容」）：普通可编辑表单字段不必写。仅当有两类特殊字段时在「交互」写清——① **非本表单录入、从别处带出**；② **用户改某字段后连带重算的只读结果**。参与联动的**可编输入须同时写清取值范围**。无此类字段 → 不写  
>   例：生产需求总数来自清单只读；可用库存打开时取库存台账可用量，置灰展示。改预占库存后，申请采购数量 = 生产需求总数 − 预占，自动回写；预占库存不能超出生产需求总数。
>
> - 搜索条件如果需要记忆，须明确说明  
>   例：工作令筛选需记忆：关闭查看弹窗后再打开，保留上次所选工作令及已生效的筛选结果（搜索后保存记忆，点「清空」后删除记忆）。
>
> **逻辑**（开发、测试看）：
>
> - **可执行条件**（何种业务状态下才允许操作）  
>   例：只有未使用状态才可以删除。
> - **唯一性**（新增 / 编辑/导入唯一性校验）  
>   例：同一工作令下设备名称不能重复。
> - **执行后本模块的业务变更**（状态变更,如果只是表单的保存则无需写,但是操作的3要素要表明,如审核虽然页面没有审核人和时间但是也要记录）  
>   例：业务状态变为已核查，记下核查人、核查时间。
> - **执行后在其他模块生成业务数据**：须写明生成规则；有单号、类型、状态等规则的一并写清  
>   例：按所选核查行逐条创建标准配件采购申请单（主表 + 默认采购明细）；申请来源=电气件清单；申请状态=待采购；申请单号规则 `CG`+`yyyyMMdd`+`-`+3 位流水，如 `CG20260727-020`。
> - **导入功能常见逻辑**（数据已存在时：不允许导入，或覆盖 / 更新，须写清楚）  
>   例：工作令下已有本模块数据则禁止导入。
> - **列表数据范围 / 汇总规则**：**不是每张列表都写**。本页默认维护本模块主数据、无额外过滤时可不写。以下情况须写清：**数据从哪来**、**按什么维度汇总 / 分组**、**哪些行进 / 不进列表**。**进度分子分母的展示口径写在「交互」**，**不要写进本条逻辑**。默认 CRUD 全量列表 → 不写  
>   例：数据范围：仅展示由设备采购清单执行「发起采购申请」后生成的申请；本模块不允许手工新增。

## 3. PDA 端

> **【模板用途｜勿写入具体业务 PRD】**  
> 字典仍只写在 **1.2**，这里不重复。仅 PDA 才有的状态，也写在 1.2，并注明「仅 PDA」。  
> 三维与第 2 章相同：`##### 页面元素` → `##### 交互` → `##### 逻辑`。下面只写和 Web **不一样** 的地方。
>
> **按「页面」拆 `###`：**
>
> ```text
> ## 3. PDA 端
> ├── ### 3.1 某某页面              ← 入口页（卡片列表 + 本页查询/扫码/确认）
> │     ├── #### 列表页面
> │     ├── #### 查询 / 扫码 …
> │     └── …
> └── ### 3.2 某某详情/查询页面    ← 从 3.1 点进去的全新页（自带返回、自己的按钮）
>       ├── #### 列表页面 或 详情页面
>       └── #### …
> ```
>
> **何时写 `### 3.2`（及 3.3…）：**  
> 点卡片、按钮或扫码成功后进入 **另一个页面**（有自己的导航标题，返回上一页），且该页自己还有列表、按钮或一整块详情 → 另起 `### 3.2`。入口页「交互」只写「进入 3.2」，不在 3.1 展开该页全部功能。  
> 确认框、底部选项（选车间、选语言等）、轻提示 → 仍写在当前 `###` 的 `####` 里，不要升成新页面。  
> **底部四个入口**（工作台 / 主页 / 扫描 / 更多）是壳，不是业务页。本模块从哪个入口进去，在 `### 3.1` 开头用一句话写清即可，不单独展开这四个壳页面。
>
> **一个页面（如 `### 3.1`）下面写什么：**
>
> ```text
> ### 3.1 生产订单页面
> ├── #### 列表页面          ← 有卡片列表才写
> ├── #### 查询              ← 本页带查询才写
> ├── #### 扫码              ← 本页带扫码才写
> └── …                     ← 有几个写几节；页面差别大则分开
> ```

> **不写**：接口、编码、库字段、菜单权限；导航栏返回；确认框的取消/确定；列表默认的下拉刷新、上拉加载（与下面默认不一致时才写）。

### 3.1. 【页面名称，如：生产订单页面】

> **【模板用途｜勿写入具体业务 PRD】**  
> 本 `###` = **一个 PDA 页面**。入口写在标题下第一句，如「从主页进入」。其下：
>
> 1. **有卡片列表** → 先写 `#### 列表页面`；无列表则跳过。列表是 **卡片**（一行一个字段名 + 值），不要写成 Web 的表格列、序号列、操作列、固定列。  
> 2. **功能点** → 本页实际有几个就写几个 `####`（查询、扫码、提交等）；没有的不写。  
> 3. **每一节三维相同**。新增/编辑基本一样 → 写成「新增/编辑」；页面差别大 → 分开。  
> 4. **点进去是全新页** → 另写 `### 3.2`。
>
> 以下「交互」「逻辑」适用于 **每一个** `####`，按需选用。每条先写规则；「例：」只供模板参考，**勿原样抄进业务 PRD**。
>
> **交互**（与 PDA 默认不一致时才写）：
>
> - **下拉刷新、上拉加载是每个列表的默认，不必逐页再写。** 下拉：回到第一页并替换当前列表。上拉：追加下一页；没有更多时显示「没有更多了」，不再加载。仅当与此不同才写。  
>   例：下拉刷新后仍保留上次的查询条件。  
>   例：本列表一次展示全部，不做上拉加载。
>
> - **查询**：点「查询」后条件在本页弹出，还是进入查询页；确认后列表如何变。  
>   例：点「查询」进入查询页；填写生产单号、合同号并确定后，返回列表并按条件过滤。
>
> - 点击 **卡片** 或卡片内区域后的跳转（非默认无反应）。  
>   例：点击卡片进入生产订单详情（见 3.2）。
>
> - **扫码**：扫什么、扫成功去哪、扫失败如何提示。  
>   例：扫描生产单号，命中则进入该单详情；未命中轻提示「未找到生产订单」。
>
> - 卡片上按钮的 **显隐 / 置灰**（随业务状态变化）。**列表上方固定按钮的显隐无需写。** 按钮多时先写一句总述，再一行一个按钮。  
>   例：
>
>   - 卡片按钮显隐和置灰：
>     - 开工：仅待开工显示
>     - 报工：进行中可点；已完工置灰
>
> - 卡片字段 **底色 / 高亮 / 加粗**（字典里已有颜色的写「见字典××」，不重复列色）。  
>   例：生产数量以蓝色加粗显示。
>
> - 卡片上 **进度或数量** 的口径（分子 / 分母、加减关系写在这里，不写进下方「数据范围」）。  
>   例：完工进度 20/50；分子 = 已报工数量，分母 = 生产数量。
>
> - **空列表文案**：设计图画出或产品明确要求时才写。  
>   例：无数据时显示「暂无生产订单」。
>
> - 无值显示 `-`：**不是默认**。设计图画出或本文写明才写；多个字段并成一行。未画、未写 → 整条不写。  
>   例：合同号、备注无值显示 `-`。
>
> - **表单特殊字段**（同 Web）：只写两类——从别处带出的只读值；改某字段后连带重算的只读结果。可编输入须写取值范围。普通手填字段不写。  
>   例：生产单号由扫码带出，只读；合格数量不能大于生产数量，不合格数量 = 生产数量 − 合格数量，自动回写。
>
> - 查询条件需要 **记忆** 时才写。  
>   例：查询条件需记忆：返回列表再进查询页，保留上次条件；点「清空」后删除记忆。
>
> **逻辑**（与 Web 相同，按本页实际选用）：
>
> - **可执行条件**  
>   例：只有待开工才可以开工。
> - **唯一性**  
>   例：同一生产单不允许重复报工。
> - **执行后本模块的业务变更**（只是保存表单且无状态变化则不写；审核等看不出的操作人、时间仍要写）  
>   例：状态变为进行中，记下开工人、开工时间。
> - **执行后在其他模块生成或回写数据**（含回写 Web 同一业务）  
>   例：报工提交后，Web 报工记录同步出现该条，状态为待审批。
> - **扫码或提交时数据已存在**：不允许，或覆盖 / 更新，须写清楚。  
>   例：该生产单已有未完成报工则禁止再次扫码开工。
> - **列表数据范围**：默认就是本模块该入口下的全量列表时不写。数据从哪来、哪些行不进列表时要写。进度口径不要写进本条。  
>   例：仅展示当前登录人、当前车间下的生产订单；已关闭的不显示。
