# 分托管理模块 PRD 文档

---

## 1. 基本说明

### 1.1. 业务理解

分托管理用于把在库料品从原托盘调整到另一个托盘（分托 / 组托），并留下可追溯的调整记录。现场操作全部在 PDA「托盘调整」完成：先扫要分入的托码，再逐个扫料品码，选好库位后确认。确认后这批料品码改绑到新托码；非车间人员同时把料品码的仓库、货架、库位改到所选位置。Web 只做记录查询、查看料品明细和导出，不能新增、编辑或删除。

另一类操作是解绑：在 PDA「解绑」逐个扫要解绑的料品码后确认，这批码不再绑定任何托盘。解绑记录在 Web「分托解绑」页面查询。

```text
PDA 托盘调整（同一人同时只有一条进行中，退出后再进入会自动带出）
├─ 扫分入托码 → 判定新托 / 老托
│    ├─ 新托：手动选库位，或扫货架码后选层数
│    └─ 老托：库位、仓库自动带出原托位置，不可改
├─ 扫料品码 → 料品码被锁定，按料品汇总展示
├─ 扫码删除 → 从本次调整中移除该码，解除锁定
├─ 返回且一个料品码都没扫 → 放弃本次调整
└─ 确认 → 料品码改绑新托码（非车间人员同时改仓库、货架、库位），解除锁定
        ↓
分托记录变为已完成 → Web「分托管理」可查询、查看、导出

PDA 解绑（同一人同时只有一条进行中）
├─ 扫料品码（必须已绑定托盘）→ 料品码被锁定，按料品汇总展示
├─ 扫码删除 → 从本次解绑中移除该码，解除锁定
└─ 确认 → 料品码清除托码，解除锁定
        ↓
解绑记录变为已完成 → Web「分托解绑」可查询、查看
```

**两端分工：**

- **Web**：「分托管理」查询已完成的分托记录、导出组托物料，进入详情查看料品明细；「分托解绑」查询已完成的解绑记录，进入详情查看料品明细。全部只读。
- **PDA**：
  - 「托盘调整」：扫托码、扫料品码、扫货架码、选库位和货架层数、扫码删除、确认分托；点料品卡片查看该料品下已扫的每一个码。
  - 「解绑」：扫料品码、扫码删除、确认解绑；点料品卡片查看该料品下已扫的每一个码。

**车间人员与非车间人员：**登录人所属部门类别为「车间」时视为车间人员。

| 对比项 | 非车间人员 | 车间人员 |
| ---- | ---- | ---- |
| 能扫的托码、料品码（托盘调整、解绑都适用） | 必须在库中 | 不能在仓库（非线边仓）里 |
| 托盘调整页头 | 显示库位编码、货架层数、仓库名称 | 只显示分入托码 |
| 托盘调整确认前是否必须选库位 | 必须 | 不需要 |
| 托盘调整确认后改什么 | 托码、仓库、货架、库位 | 只改托码 |

### 1.2. 字典说明

#### 分托类型

| 类型值 / 状态值 | 说明 |
| --------------- | ---- |
| 分托 | 由 PDA「托盘调整」生成，在 Web「分托管理」页面查询。 |
| 解绑托码 | 由 PDA「解绑」生成，在 Web「分托解绑」页面查询。 |

#### 分托状态

页面上不展示状态，只用来区分 PDA 进行中的任务和 Web 可查询的记录。

| 类型值 / 状态值 | 说明 |
| --------------- | ---- |
| 进行中 | PDA 已扫码但未确认。同一人、同一分托类型同时只能有一条进行中，再次进入 PDA 页面会自动带出这一条。Web 不展示。 |
| 已完成 | PDA 已确认。Web 只展示已完成的记录。 |

#### 托盘类型

仅 PDA 使用，扫分入托码时判定。

| 类型值 / 状态值 | 说明 |
| --------------- | ---- |
| 新托 | 系统中还没有任何料品码绑定过的托码。非车间人员需要手动选库位，或扫货架码后选层数。 |
| 老托 | 已有料品码绑定的托码。库位、仓库自动带出原托所在位置，不能修改。 |

## 3. PDA 端

> 字典见 1.2。
>
> 设计图没有侧边硬件键，需要扫码的页面或弹层都放一个「扫码」按钮，点它等同于源码里按一次侧边键。源码里「侧边按钮扫码」这类文案，设计图统一写成「点扫码」，其余文案与源码一致。设计图不播放扫码提示音。
>
> 本模块 PDA 页面都不分页，一次展示全部，没有下拉刷新和上拉加载。系统返回键（侧滑、物理返回）不生效，只能点导航栏左侧返回。

### 3.1. 托盘调整页面

**入口：**主页「物流管理」分类下的「托盘调整」。

#### 列表页面

##### 页面元素

**导航栏标题：**托盘调整；左侧「返回」。

**页头：**蓝色加粗小标题「分入托码」，下面是整宽白底信息区，每行左标签、右内容。

| 字段 | 说明 |
| ---- | ---- |
| 分入托码 | 扫码带出；未扫时显示「点扫码」 |
| 库位编码 | 整行可点；有值显示库位编码；无值时，新托显示「请选择库位/点扫码」，其它情况显示「自动带出/手动选择」 |
| 货架层数 | 扫到货架码后才出现；显示已选层数，右侧下箭头 |
| 仓库名称 | 有值显示仓库名称；无值显示「自动带出」 |

页头下方红色加粗提示「请点扫码扫料品码」。

**列表上方的按钮：**无

**卡片展示字段：**按料品汇总，一个料品一张卡片，白底。

| 字段 | 说明 |
| ---- | ---- |
| 料品名称 | 过长省略 |
| 料品编码 | |
| 二维码数量 | 该料品已扫的码数 |
| 料品总量 | 该料品已扫码的数量之和 |
| 料品单位 | |
| PO号 | 多个用逗号隔开 |

**卡片上的按钮：**无

**页面按钮：**底部贴边整宽蓝色「确认」。右下角两个圆形悬浮按钮：上为蓝色「扫码」，下为红色「扫码删除」（文字分两行「扫码」「删除」）。

##### 交互

- 料品名称、料品编码、料品单位、PO号无值显示 `-`；二维码数量、料品总量无值显示 `0`。
- 车间人员只显示「分入托码」一行，不显示库位编码、货架层数、仓库名称。
- 进入页面时读取本人进行中的托盘调整：有则带出分入托码、库位编码、仓库名称和已扫料品卡片；没有则页头显示占位文案，列表为空。
- 点卡片进入托盘调整详情（见 3.2），展示该料品下已扫的码。
- 点导航栏「返回」：
  - 有进行中的托盘调整，但一个料品码都没扫：放弃本次调整，成功后回到主页；下次进入是空页面
  - 其它情况：直接回到主页，进行中的数据保留，下次进入继续

##### 逻辑

- 数据范围：当前登录人进行中的这一条托盘调整（分托类型 = 分托）下已扫的料品码，按料品汇总。
- PO号取该料品已扫码关联的销售订单合同号，去重后用逗号拼接。
- 放弃本次调整：解除所有已扫码的锁定，删除这条进行中的记录。只有已扫了托码、还没扫料品码，或扫过又全部删掉时才会发生。

#### 扫码

##### 页面元素

无（使用页面右下角「扫码」）。

##### 交互

- 点「扫码」后按扫到的码分三类处理，其它码提示「请扫描正确的二维码」，页面不变。
  - **托码**（载具码，第 2 位为 P）：先清空库位编码，再带着这个托码提交。成功后分入托码换成新托码，判定新托 / 老托：老托带出原托的库位编码、仓库名称；新托库位编码为空，需要重新选
  - **料品码**（载具码，第 2 位为 E 自制成品、F 外购成品、M 倒轴）：带着当前分入托码、库位编码、仓库提交。成功后列表按料品重新汇总，二维码数量、料品总量随之变化
  - **货架码**（8 位数字，前 4 位工厂编码、后 4 位货架编码）：查货架信息。成功后库位编码显示货架编码，仓库名称带出，出现「货架层数」行（层数为空），等待选层；失败提示「货架信息获取失败」或系统返回的原因
- 原材料码（第 2 位为 R）不属于以上三类，提示「请扫描正确的二维码」。
- 提交失败：提示系统返回的原因（无原因时提示「扫码失败」），重新读取进行中的数据，页头和列表恢复为扫之前的样子；扫托码失败时分入托码也恢复为扫之前的值。网络异常提示「扫码失败，请重试」。
- 库位显示规则：扫过货架码时，提交成功后库位编码仍显示货架编码和已选层数；否则显示系统返回的库位编码。

##### 逻辑

- 首次扫码时生成一条进行中的托盘调整，记下操作人和时间；之后的扫码都写到这一条上。本人已有进行中的托盘调整时，不会再生成第二条。
- 扫托码：
  - 系统中没有料品码绑定过该托码，判定为新托
  - 有料品码绑定过，判定为老托，库位、仓库取原托所在位置
  - 老托，非车间人员：该托必须在库中，否则提示「存在托码未在库」
  - 老托，车间人员：该托在仓库（非线边仓）里时，提示「不可扫描在仓库里面的托码」
- 扫料品码，以下情况不允许装入，提示括号内文案：
  - 码不存在（系统提示码不存在）
  - 扫的是托码这类包含多个码的父码（「请扫描单品码」）
  - 一个码对应多个料品，不是一物一码（「只可扫码一物一码的料品码」）
  - 非车间人员扫的码不在库中（「存在单品码未在库中」）
  - 车间人员扫的码在仓库（非线边仓）里（「不可扫描在仓库里面的码」）
  - 本次已扫过（「扫描的单品码不可重复」）
  - 与已扫料品码不在同一仓库（「扫码的单品码必须是同一仓库的」）
  - 与分入托码所在仓库不同（「扫的单品码和分托的托码必须为同一个仓库的」）
  - 已被其它业务锁定（「当前二维码的根码已经锁定无法操作」）
  - 当前仓库已锁定，如盘点中（「仓库已锁定」）
- 装入成功后：该码按扫码时的托码、仓库、货架、库位记下一条明细；该码被锁定（锁定动作 = 分托），确认或删码前其它业务不能操作它。
- 本次调整的仓库取已扫料品码所在的仓库。

#### 选择库位 / 货架层数

##### 页面元素

**库位选择：**底部弹层，高约 80% 画布，浅灰底。顶部白色圆角搜索框，提示「搜索库位」，右侧搜索图标。下方左右两栏：左栏（约 40%）仓库列表，选中项蓝底白字，仓库名为空时显示「暂无数据」；右栏（约 60%）为所选仓库下的库位，一行一个，居中；库位有备注时，库位编码与备注左右各占一半。

**货架层数：**底部弹层，高约 80% 画布，一行一个层数，行间有分割线。

##### 交互

- 点「库位编码」整行，按顺序校验，不满足只提示、不打开：
  - 老托：「当前状态不能选择」
  - 未扫托码：「请扫描托码」
  - 还没扫料品码：「请扫描料品码」
- 校验通过后打开库位选择，默认选中第一个仓库，右栏展示它的库位；读取仓库失败提示「获取仓库列表失败」。
- 点左栏切换仓库，右栏换成该仓库的库位。输入库位号后点搜索图标，右栏按库位号过滤。
- 点右栏某个库位：库位编码、仓库名称换成所选值，清空并隐藏货架层数，关闭弹层，再把库位提交到本次调整。
- 点「货架层数」行：先重新读取该货架的层数（已选层数清空），再打开层数弹层；读取失败提示「查询货架层数失败」。点某层后写回货架层数，关闭弹层，再把库位提交到本次调整。
- 点遮罩关闭弹层，库位不变。

##### 逻辑

- 左栏只列当前登录人部门下、已启用、且与已扫料品码同一仓库的仓库。
- 提交的库位：选库位时为所选库位编码；选货架层数时为「货架编码-层数」。所选库位在该仓库下不存在时，提示「库位不存在」。
- 老托不能改库位：选库位入口不可用；扫货架码选层后提示「原托已经入库,不可以赋值不同的库位」，库位不变。
- 只扫货架码、不选层数时，库位不会写入本次调整。

##### 交互

- 点「完成删除」：
  - 成功：关闭弹层，列表按料品重新汇总，提示「删除成功」

  - 还没扫就点：提示「请传入二维码」，弹层保持打开

- 点「扫码」只查询该码信息，用于删除前核对，不改本次调整的数据。

- 本次调整已确认完成时不允许删除（「当前分托单已经完成无法操作」）。

  - 非车间人员：已选库位（「当前库位还未选择」），已带出仓库（「当前仓库还未选择」），且该仓库未锁定（「仓库已锁定」）
  - 已扫分入托码（「当前托码未扫码」）
- 执行后：
  - 本次所有料品码改绑到分入托码，并解除锁定
  - 非车间人员：料品码的仓库、货架、库位同时改为本次所选位置；车间人员不改
  - 托盘调整状态变为已完成，记下仓库（取料品码所在仓库）
  - Web「分托管理」列表出现这条记录，组托人员、组托时间为本次操作人和首次扫码时间
  - 库存统计按这批料品码重新统计

#### 扫码

##### 页面元素

无（使用页面右下角「扫码」）。

##### 交互

- 点「扫码」：
  - 载具码（第 2 位为 E、F、M、P）：提交本次扫到的码。成功后列表按料品重新汇总
  - 其它码（含第 2 位为 R 的原材料码）：提示「请扫描正确的二维码」，页面不变
- 托码（第 2 位 P）能通过格式判断，但提交后提示「请扫描单品码」。
- 提交失败：提示系统返回的原因（无原因时提示「扫码失败」），列表不变。网络异常提示「扫码失败，请重试」。

##### 逻辑

- 首次扫码时生成一条进行中的解绑，记下操作人和时间；之后的扫码都写到这一条上。
- 以下情况不允许装入，提示括号内文案：
  - 码不存在（系统提示码不存在）
  - 扫的是托码这类包含多个码的父码（「请扫描单品码」）
  - 一个码对应多个料品，不是一物一码（「只可扫码一物一码的料品码」）
  - 非车间人员扫的码不在库中（「存在单品码未在库中」）
  - 车间人员扫的码在仓库（非线边仓）里（「不可扫描在仓库里面的码」）
  - 该码没有绑定托盘（「存在单品码还未绑定托」）
  - 本次已扫过（「扫描的单品码不可重复」）
  - 与已扫料品码不在同一仓库（「扫码的单品码必须是同一仓库的」）
  - 已被其它业务锁定（「当前二维码的根码已经锁定无法操作」）
- 装入成功后：该码按扫码时的托码、仓库、货架、库位记下一条明细；该码被锁定（锁定动作 = 分托），确认或删码前其它业务不能操作它。
