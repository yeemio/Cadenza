## 2. 一笔业务事实的生命周期

`上游指令／人工授权 → 数据和工艺准备 → 派工 → 实际操作 → 提交／审核 → 质量放行 → 库存／交付 → 外部对账 → 纠正或历史保留`。

贯穿每一步记录企业／工厂、对象身份、版本、操作者、实际时间与业务班次、原命令和结果。状态分别回答：现场是否发生、系统是否入账、质量是否放行、外部是否确认。任何一个绿灯都不能代替其余状态。

## 3. 当前责任与更新规则

- 本聊天维护本次规划与产品层入口；当前未建立工程派工链，也未绑定新的 RunKit 执行账本。正式工程派工时再按项目授权与安装事实选择适当连续性记录。
- `Cadence-PM` 是具名方法咨询来源；它的既有 Cadence 职责、执行者、候选和账本保持独立。
- 只在 Owner 范围决定、稳定交付、接受／返工／阻塞、部署读回或业务结果发生时更新受影响行；无变化不巡检、不催问、不建立定时器。
- 接受记录写清对象与边界：设计、源码、组合运行、安装材料、真实岗位或业务结果。失败、未测、未知和部分完成保留，不能只统计成功分母。
- 后续更改以新版本和明确替代关系衔接，来源 PRD 保持原字节；对应问题、场景和任务沿用原 ID，避免形成第二套账。
