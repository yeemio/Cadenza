# P1 范围边界说明 — SCOPE-MAP P2 标注与 T08/T12/T13 P1 归属的张力（scope-boundary-note）

版本：L2 冻结合同候选 v1 附件｜2026-10-28｜WorkItem：`L2-T01-T02-CONTRACTS`
状态：**待 PM 裁定**。本说明不改变 SCOPE-MAP；两个选项的落地写法均已预留，PM 选定其一后由 L2 补一行裁定记录即可，不需重写本批合同。

## 1. 张力陈述（证据）

`architecture/task-packages/three-package-delivery-20261027/SCOPE-MAP.md`：

- §1 任务主责任：**T08**（G2 采购收货、批次、明细、来料检验及价格复核）＝P1；**T12**（G2 最小过程／成品检验与质量放行）＝P1；**T13**（G2 待入库、成品入库、移库与调拨主链）＝P1。
- §2 原件主要行为闭合包：**移库管理（PRD-029）＝P2**（对应任务 T13、T17）；**调拨入库（PRD-037）＝P2**、**调拨出库（PRD-038）＝P2**（均 T13、T17）；**采购质检（PRD-045）＝P2**（T08、T18）；**质量存疑（PRD-039）＝P2**（T12、T18）。
- §4 场景：A02（采购→收货→来料检验→上架/退货）阶段实现 P1、P2；A06（检验→隔离→处置→放行）P1、P2、P3；A07（待入库→成品入库→移库→调拨在途→收货）P1、P2、P3。

即：**消费这些原件的任务是 P1 主责任，但原件的完整行为闭合被标在 P2**。P1 期间这五份原件只做"主链必需子集"，完整行为在 P2 闭合——这个"子集边界"SCOPE-MAP 未逐条给出，需 PM 裁定后写入域合同，否则 L1/L3 实施会各自猜测。

同型情况（本说明一并登记，不扩大裁定范围）：采购批次 PRD-042＝P2（T08、T17）；分托管理 PRD-004、倒轴记录 PRD-021、轴码清空 PRD-027、轴号修正 PRD-040＝P2（T15）；库存统计 PRD-013、报工记录 PRD-035＝P2（T20）。

## 2. 选项一（维持 SCOPE-MAP 现状，最小子集进 P1）——L2 建议默认

**语义**：五份原件按"P1 最小子集／P2 完整闭合"分层；P1 只实现主链（A02/A06/A07 的 P1 阶段项）必需行为，其余行为显式推迟。

**落地写法**（PM 选定后生效）：后续 T08/T12/T13 域合同的每条规则带 `【P1 最小】` 或 `【P2 完整】` 标签；本批 frozen/p1 合同中以下条款属 P1 最小集（建议边界，PM 可增删）：

| 原件 | P1 最小子集（建议） | 推迟 P2（建议） |
| --- | --- | --- |
| 移库管理 | 同仓库位移动命令（校验同仓/未锁定/在库/托整移/原库位≠新库位），供上架纠偏与库内整理 | 移库单据台账全量页面、跨仓移动之外的扩展校验 |
| 调拨出库/入库 | ① 收货入线边仓且公司未跳过中转→自动生成调拨出库单（生成即已出库）；② 两段原子步（来源减+在途增／在途减+目的增，IT-25）；③ 调拨入库 PDA 逐码上架（固定库位路径） | 无任务 PDA 调拨、Web 有任务建单全流程、部分数量调出（随 CA-7）、跨厂接收事实（S06）、剩余回写展示层 |
| 采购质检 | 首检记录（待质检/免检）、批次 6 态汇总投影、PDA 单码合格/不合格提交、Web 判定合格/不合格（结论版本化，随 CA-4）、撤销质检（保留关联，S14） | 复检流程、质检附件、批量质检补录细节、让步处置 |
| 质量存疑 | PDA 扫码标记存疑（在库+在库位+未存疑，托码拒）、存疑不入可用量/拒发运闸门（IT-14）、恢复=处置记录（随 CA-6） | 存疑记录分析维度、处置链扩展 |
| （同型）采购批次 | 批次/明细生成、质检联动、合格/退货回传（IF-09/10）、退货走反向流水（S05/S14 方向） | 管理员修改路径（随 CA-3）、批次删除替代流程、价格复核全量页面 |

**验收绑定**：P1 验收只主张上表左列行为；SCOPE-MAP §2 的 P2 标注不变。
