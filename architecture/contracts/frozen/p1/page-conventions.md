## 3. 扫码反馈与命令上下文

| 编号 | 规则（可判定） | 溯源 |
| --- | --- | --- |
| PC-04 | 扫码处理次序：先识别码类型与对象，再按当前任务校验；成功、失败、待确认各只有一种反馈形态。 | SA §6.1 |
| PC-05 | 错码或查询失败时立即清除不适用的旧对象（不残留上一码信息）；无任务或失败清空旧对象。 | SA §6.1；PI K13 |
| PC-06 | 数量与单位必须同时呈现；任务、库位、工序切换不得保留错误关联；不同单位不直接汇总。 | SA §6.1；PI K08 |
| PC-07 | 每个扫码入口生成显式 ReportContext（订单、工序、设备、班次、来源、操作者）；入口不读取上次页面残留作为业务上下文；同机台多道工序必须明确选择，不默认取第一条。 | SA §6.1；PI K13；底稿03 §A6 |
| PC-08 | 同一命令在各入口（Web/PDA/多页面）采用同一套仓库、库位、质量规则：前端即时提示＋服务端最终校验，两者冲突以服务端为准。 | PI K06；底稿01 §A④-52 |
| PC-09 | 空码不能提交；错误发生后保持可继续操作状态，只删除当前草稿的合法对象。 | PI K07 |

## 4. 按钮与服务端守卫

| 编号 | 规则（可判定） | 溯源 |
| --- | --- | --- |
| PC-10 | 按钮（含列表操作栏、卡片按钮）的显隐/置灰条件与服务端守卫一一对应；服务端拒绝时返回可判定错误，不依赖前端拦截。 | PI K15；底稿01 §A④-52 |
| PC-11 | 未交付能力不显示可用按钮；入口合同未定义的能力不得以"文字提及"冒充已交付。 | PI K02/S01；底稿03 §B-2 |
| PC-12 | 草稿状态不能执行审核类命令；一张报工单只承载一道工序。 | PI K15 |
| PC-13 | 删除/撤销类按钮必须显式展示后果（如删除草稿行的影响），不得以数量改 0 等隐式方式删除生效事实。 | PI K17 |

## 7. 弱网与草稿边界

| 编号 | 规则（可判定） | 溯源 |
| --- | --- | --- |
| PC-20 | 断外网时工厂内私有部署继续服务，外部接口（ERP/DC）排队；PDA 与服务器断开时可查看已缓存任务、保存本机草稿并明确显示"未提交"。 | SA §6.2 |
| PC-21 | 库存消费、最终报工审核、形态转换、发运不得显示虚假的离线成功；此类命令必须服务端入账成功才算成功。 | SA §6.2 |
| PC-22 | 本机草稿按账号、工厂、订单、工序、设备/来源、版本隔离；退出账号不继承给下一人；恢复时先校验服务端版本，冲突交给操作者选择合法动作，不做最后写入覆盖。 | SA §6.2 |
