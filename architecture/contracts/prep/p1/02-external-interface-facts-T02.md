## C. 对底座（command_receipt/outbox/inbox）的影响点

1. 出站任务状态机须支持多态而非二态：无需同步（实发轴第四态）、转换失败/同步失败两阶段（库存形态转换 §1.2）。
2. 单聚合多并行回传流：采购批次（合格+退货）、成品出库（实发轴+发货状态）→ outbox 需 (聚合类型, 聚合ID, 任务种类) 复合身份，非每聚合一任务。
3. 任务载荷须固化业务时点快照：“按出库完成时间重推发货状态”（成品出库 §2.1）——重试不能改推当前值。
4. 外部优先协议需“外部结果未知”中间态+“已成功外部步骤不重做”幂等标记（库存形态转换 重新同步不再推 U9）。
5. inbox 需 (来源系统, 组织, 外部业务键, 实体类型) 唯一约束：dcId、采购单号+行号、生产单号、发货单号、料品编号+组织编码均有原文锚点；外部修订号/序号原文无字段，合同须显式引入并允许空值+校验规则。
6. 隔离队列落地：缺组织/单位/工作中心映射的入站数据进隔离态可人工补绑（架构 §5，对应工作中心对照表补绑场景），不是普通失败重试。
